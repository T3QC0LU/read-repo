# Context — read-repo skill

## Glossary

**READREPO.md**
An analysis report generated by the read-repo skill. Targeted at developers who are taking over a codebase, learners who want to understand a project, and open-source contributors who want to fork or modify it. It is NOT a replacement for the project's own README.md. It is an analytical document authored by the agent, not the project author.

**README.md**
The project's own face document, written by the project author. Aimed at external users and contributors. Not generated by this skill.

**Mode**
The user's intent when invoking the skill. Determines the emphasis and structure of the generated READREPO.md. Three modes are defined: `learn`, `takeover`, `hack`. Default is `learn` when no explicit intent is stated.

**scan.sh**
A bash script that performs mechanical, best-effort data collection from a repository. Outputs directory tree, language breakdown (by file count, not line count), manifest files, entry points, config files, and test directories. It is a data-collection accelerator, not an authoritative source. The agent's Phase 2 deep read is the authoritative information source. scan.sh output may be incomplete or imprecise.

**`⚠️ inferred`**
An inline marker applied at the field level in generated documents to indicate that a value was reasoned from indirect evidence rather than confirmed directly from code or explicit documentation. Applied immediately after the value, e.g. `Pattern: Hexagonal ⚠️ inferred`. Used throughout all generated documents. Users are expected to review and confirm or correct inferred fields.

**Monorepo**
A repository containing multiple independently deployable or publishable packages, typically under `packages/`, `apps/`, or `services/` directories, and usually signaled by `lerna.json`, `pnpm-workspace.yaml`, `nx.json`, `rush.json`, or a `workspaces` field in the root `package.json`. When a monorepo is detected, the skill generates a READREPO.md per package (in the package directory) plus a top-level READREPO.md describing inter-package relationships and overall structure.

## Decisions

- `READREPO.md` coexists with the target repo's `README.md`; they serve different purposes and different audiences.
- The skill operates in one of three modes — `learn`, `takeover`, `hack` — determined by user intent before document generation begins.
- Default mode is `learn`.
- Core Points are defined as non-obvious insights that meet at least one of: (1) apparent bad practice with a deliberate reason, (2) critical logic hidden in unexpected locations, (3) naming that misrepresents actual behaviour, (4) important performance or security constraints, (5) non-standard extension patterns. Core Points appear in all generated READREPO.md files under the section `## ⚡ Core Insights`.
- `READREPO.md` is the entry document and stays readable (target: <300 lines). Deeper content lives in separate files (ARCHITECTURE.md, FOLDER-GUIDE.md, etc.) linked from READREPO.md. Separate files are generated based on mode + repository complexity, not complexity alone.
- scan.sh is a best-effort data-collection accelerator (R2). It is not authoritative. Phase 2 deep read is the authoritative source. scan.sh bugs do not block document generation.
- scan.sh uses a single unified exclusion list shared across both `tree` and `find` invocations. User-configurable ignore rules (S2, `.repoignore`) are deferred to backlog. When implemented, `.repoignore` uses `.gitignore` syntax; the repo's own `.gitignore` is read first, then `.repoignore` is overlaid with higher priority.
- Every generated READREPO.md begins with a mode callout on line 1: `> 🔍 Generated in **{mode}** mode by read-repo. Re-run with "{example prompt}" to switch modes.`
- In a monorepo, each package gets a `READREPO.md` inside its own directory. The root also gets a `READREPO.md` describing inter-package relationships. No package-name suffixes in filenames — the directory path already disambiguates.
